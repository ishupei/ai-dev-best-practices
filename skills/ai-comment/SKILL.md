# Java 注释补全

只为本次新增/变更 Java 代码补充有价值注释：类/方法用 Javadoc，数据承载类属性必须有说明，方法体关键逻辑块用中文 `//` 单行注释。禁止改业务逻辑、逐行注释、注释未波及历史代码。

## 范围

- 输入优先级：用户指定范围 > 当前对话新增/修改代码 > Git 工作区新增/变更 Java 文件。
- 范围不明确时先询问，**MUST NOT** 扫描或批量改动全仓库。
- **MUST NOT** 给历史未改动、未被本次任务波及、仅路过阅读到的类/方法补注释。
- 历史方法即使被新增代码调用，只要本次未修改且不需要同步注释，**MUST NOT** 修改其注释。
- 需要处理历史代码时，必须先说明直接关系并获得用户确认。

## 注释规则

- Javadoc：用于新增/变更的类、接口、枚举、公开/受保护方法、核心私有方法；只写职责、业务语义、参数、返回、异常/边界。**MUST NOT** 描述完整执行流程。
- 属性说明：Entity、DTO、VO、BO、PO、Form、Query 等数据承载类的新增/变更属性 **MUST** 有注释，说明业务含义、单位/格式、枚举值或约束；不得只重复字段名。
- 方法内注释：用中文 `//` 放在关键逻辑块前，说明分支业务含义、决策原因、外部调用目的、数据转换或状态变更。流程节点如需说明，只能放在方法体内。
- 注释价值：所有注释必须提供信息增量；不得重复代码动作、方法名、字段名，不写“以下代码用于...”等空泛句。
- 注释密度：普通方法通常 1-4 条方法内注释；复杂方法可增加，但必须对应关键逻辑块。**MUST NOT** 逐行注释。
- 风格：沿用项目既有注释风格；不得为注释新增依赖；已有准确注释保留，过时/空泛注释修正。

## 工作流程

1. 锁定本次新增/变更 Java 范围，只读查看必要上下文。
2. 理解业务语义、参数返回、分支、异常和状态变化，避免凭名称猜注释。
3. 只新增/修正注释；除注释格式外 **MUST NOT** 改代码。
4. 自查：范围未扩大、Javadoc 不写流程、属性有说明、方法内注释有价值且非逐行。
5. 输出摘要：处理文件、注释类型、无法确认的业务语义。

## 完成自检

- 未处理未改动、未波及历史代码。
- Javadoc 只写职责和契约，不写完整流程。
- 数据承载类新增/变更属性都有业务含义说明。
- 方法内注释只标关键逻辑块，不逐行、不空泛。
- 只改注释，不改业务逻辑。
