# /ai-do 核心执行规范

## 1. 适用范围

- 1.1 适用于 `/ai-do` 下的代码生成、修改、测试、配置和文档落地。
- 1.2 输入允许是实现指令、TASK/PLAN/DRAFT/DESIGN，或仅对话上下文中足够明确的需求；需求足够明确时 **MUST NOT** 要求先补 TASK/PLAN。
- 1.3 无 TASK 文档时，只在对话中汇报步骤进度，不为进度新建或改写文档。

## 2. 规则优先级

- 2.1 **MUST** 优先遵循用户本轮明确指令。
- 2.2 **MUST** 其次遵循 TASK / DESIGN / PLAN / DRAFT 中的硬性约束。
- 2.3 **MUST** 再遵循当前技能目录下的 `SKILL.md` 与本 references 中的规范。
- 2.4 目标代码目录的现有风格、命名、分层和测试组织 **MUST** 优先于通用最佳实践。
- 2.5 规则冲突且无法按优先级裁决时，**MUST** 中断并说明冲突点，**MUST NOT** 自行折中。

## 3. 编码前强制动作

- 3.1 识别输入来源、验收口径、边界条件和直接相关文件。
- 3.2 识别技术栈：构建文件、依赖、目录、主语言、测试框架和现有风格。
- 3.3 识别目标目录中的既有模式：命名、分层、异常处理、日志、依赖注入、工具类和测试组织。
- 3.4 输出执行契约：目标、范围内、范围外、预计修改、验证等级、中断闸门。
- 3.5 输出编码前检查单：技术栈、已读规范、专项规则启用情况、关键条款编号。
- 3.6 未完成执行契约和检查单前，**MUST NOT** 修改文件。
- 3.7 多步骤执行时，首个步骤 **MUST** 输出完整契约；后续步骤 **MUST** 只输出相对上一项变化的字段和新增关键条款。

## 4. 生成代码硬性要求

- 4.1 **MUST** 优先复用项目已有模式，**MUST NOT** 引入与现有风格明显不一致的新写法。
- 4.2 **MUST** 保持命名风格一致：包名、类名、方法名、变量名、常量名、DTO/VO/Entity 命名等。
- 4.3 **MUST** 保持目录结构一致，**MUST NOT** 随意新增层级或跨层放置文件。
- 4.4 **MUST** 只实现当前任务要求，**MUST NOT** 顺手重构无关代码。
- 4.5 **MUST** 控制改动范围，**MUST** 优先局部修改。
- 4.6 顺手修改是当前任务前置条件时，**MUST** 在结果中说明原因。
- 4.7 新增成员或相近逻辑时，**MUST** 先查找语义相近的现有成员并紧邻其后生成；无相近成员时置于同类成员区末尾，无法划分时置于文件末尾。
- 4.8 对本次新增或修改的可内联方法，若方法体少于 5 行且只被调用 1 次，**MUST** 内联到调用处。接口实现、方法覆写、框架回调和外部契约方法除外。
- 4.9 **MUST** 让控制流清晰，避免过深嵌套、重复逻辑与含义不明的临时变量。
- 4.10 **MUST** 做必要的空值、边界、异常或失败分支处理。
- 4.11 **MUST** 保持接口输入输出语义清晰，避免隐式副作用。
- 4.12 **MUST** 优先使用项目中已存在的库、工具类、基础设施与封装约定。
- 4.13 仅在逻辑不直观时添加简洁注释，解释“为什么”，不要解释显而易见的“做了什么”。
- 4.14 任务要求同步文档、示例、SQL、配置说明时，**MUST** 在本次实现中一并完成。
- 4.15 未经任务或设计要求，**MUST NOT** 新增第三方依赖、基础设施配置或跨模块耦合。
- 4.16 **MUST NOT** 引入无依据的未来扩展点、无使用方的抽象层或过度设计。
- 4.17 **MUST NOT** 因个人偏好替换项目既有实现方案或写法。
- 4.18 **MUST NOT** 顺带大面积格式化或无意义重排，避免无关 diff。
- 4.19 **MUST NOT** 为形式复用拆分方法。

## 8. 上下文与安全边界

- 8.1 无 TASK 场景 **MUST** 先读取用户指令、相关源码、构建/依赖入口、直接调用链；**MUST NOT** 默认扫描 `docs/`。
- 8.2 有 TASK 场景 **MUST** 只读取工作根目录 `docs/<功能目录名>/` 下同一需求的 TASK/PLAN/DRAFT/DESIGN。
- 8.3 代码调研 **MUST** 限定为直接相关文件、相邻模式、必要接口或测试；扩大范围前 **MUST** 说明原因。
- 8.4 预计改动超过 8 个文件、跨越超过 2 个顶层模块、需要新增依赖、修改基础设施或触及危险操作时，**MUST** 中断并报告。
- 8.5 **MUST NOT** 读取项目根 `config/`、`deploy/config/`、`.env`、密钥、证书或凭据材料。
- 8.6 同一轮执行中已读取的 reference **MUST** 复用；仅当文件被修改、条款不确定或技术栈变化时 **MUST** 重读。
- 8.7 用户可见输出 **MUST** 只列本步会影响实现或验收的内容，**MUST NOT** 复述已稳定且未变化的信息。
