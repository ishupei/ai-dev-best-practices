# /ai-do 验证与报告规范

## 5. 验证阶段强制检查

- 5.1 功能是否满足实现指令、TASK 或 DESIGN 中的验收要求。
- 5.2 是否违反核心规范中的硬性要求。
- 5.3 是否破坏现有代码风格、分层、目录或接口约定。
- 5.4 是否存在明显未处理的异常路径、边界条件或回归风险。
- 5.5 新增成员是否紧邻语义相近成员，符合 §4.7。
- 5.6 是否遗留少于 5 行且仅被调用 1 次的可内联冗余方法，符合 §4.8。
- 5.7 必须检查 `git diff`，确认改动范围等于当前任务范围；越界改动必须撤销或在报告中说明原因。
- 5.8 每步至少执行静态自检和 diff 复核。
- 5.9 已存在且低成本的格式检查、类型检查、单文件测试或局部验证命令，**MUST** 在说明命令与目的后才可执行。
- 5.10 全量构建、全量测试、新增测试代码、引入测试框架，**MUST** 由用户本轮指令或 TASK 验证方式明确要求。
- 5.11 未执行构建或测试时，报告 **MUST** 写明未执行原因，**MUST NOT** 笼统声明“测试通过”或“验证全部通过”。
- 5.12 验证失败时，**MUST** 只允许 1 次当前步骤内的最小范围修复；仍失败、无法修复或修复会扩大范围时，**MUST** 中断执行循环。

## 6. 冲突与失败处理

- 6.1 若任务要求与项目现有写法冲突，**MUST** 优先遵循任务与设计，且 **MUST** 在结果中注明偏离点。
- 6.2 若本规范与现有代码写法冲突，**MUST** 优先遵循任务与设计，并 **MUST** 尽量兼容现有风格且限制改动范围。
- 6.3 若无法判断哪条规则优先，**MUST** 中断执行循环并等待用户确认。
- 6.4 触发中断时，报告 **MUST** 包含原因、影响、已完成范围、建议处理方式和是否需要用户裁决。

## 9. 报告必填项

- 9.1 中间短报告 **MUST** 包含：任务/步骤状态、改动文件数、验证摘要、下一步。
- 9.2 最终汇总 **MUST** 包含：执行契约摘要、完成范围、变更文件与要点、验证等级与结果、技术栈判定、规范检查、TASK 状态更新、未执行验证及原因、剩余风险/后续建议。
- 9.3 最终汇总 **MUST** 包含规范读取凭证：已读 reference 文件路径和核对条款数。
- 9.4 最终报告中的验证等级 **MUST** 显式区分：静态自检、diff 复核、构建/命令、测试执行。
- 9.5 最终报告 **MUST NOT** 复述完整规范原文、完整 diff 或未触发的检查项；**MUST** 只输出结论、依据、验证结果和剩余风险。
