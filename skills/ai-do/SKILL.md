# 代码执行规范卡

作为代码落地前的最终执行关卡。输入允许是实现指令、TASK/PLAN 文档，或仅对话上下文中的明确需求；需求足够明确时，**MUST NOT** 因缺少 TASK/PLAN 而拒绝执行，但 **MUST** 先建立执行契约、读取必要规范、控制上下文预算、验证改动范围。

## 1. 输入选择

**MUST** 按以下优先级选择输入：

1. `/ai-do` 后的直接实现指令：拆成最小可验证步骤执行，**MUST NOT** 要求先 `/ai-task`，**MUST NOT** 为进度新建 TASK 文档。
2. 用户指定的任务编号或文件：从该任务开始，按依赖顺序执行。
3. 当前对话已有任务清单、前序 skill 输出或足够明确的需求：直接执行。
4. 以上都没有时，才在工作根目录 `docs/` 下递归查找 `TASK-*.md`，并读取同一功能目录的 `PLAN-*.md`、`DRAFT-*.md`；若存在 `DESIGN-*.md`，**MUST** 一并读取。多个候选时 **MUST** 先按主题、最近指令、功能目录、标题、更新时间选择并说明依据；仍不明确则 **MUST** 中断请用户确认。

无可靠输入时，**MUST** 要求用户提供实现需求。

## 2. 必读资源

编码前 **MUST** 按以下规则加载本技能目录下的 reference：

- **MUST** 先读取 `references/core-standards.md`，再读取 `references/verification.md`。
- 仅当目标项目是 Java/Spring Boot/微服务时，**MUST** 再读取 `references/java-spring.md`；非 Java/Spring 项目 **MUST NOT** 读取或套用该专项规则。
- `references/code-standards.md` 仅作为兼容索引；**MUST NOT** 只读取索引代替规则正文。
- 同一轮执行中，已读取的 reference **MUST** 复用；仅当文件被修改、条款不确定或技术栈变化时 **MUST** 重读。

## 3. 上下文预算

- 无 TASK 场景：**MUST** 先读取用户指令、相关源码、构建/依赖入口、直接调用链；**MUST NOT** 默认扫描 `docs/`。
- 有 TASK 场景：**MUST** 只读取工作根目录 `docs/<功能目录名>/` 下同一需求的 TASK/PLAN/DRAFT/DESIGN。
- 代码调研 **MUST** 限定为直接相关文件、相邻模式、必要接口或测试；扩大范围前 **MUST** 说明原因。
- **MUST NOT** 读取项目根 `config/`、`deploy/config/`、`.env`、密钥、证书或凭据材料。
- 用户可见输出 **MUST** 保持“先结论后证据”：契约、检查单、报告只列本步会影响实现或验收的内容，**MUST NOT** 复述已稳定且未变化的信息。

## 4. 执行契约

每个任务/步骤编码前 **MUST** 输出极短契约；未输出契约时 **MUST NOT** 修改文件。多步骤执行时，首个步骤 **MUST** 输出完整契约，后续步骤 **MUST** 只输出相对上一项变化的字段和新增关键条款。

```markdown
执行契约
- 目标：...
- 范围内：...
- 范围外：...
- 预计修改：... files / ... modules
- 验证等级：静态自检 / diff 复核 / 构建或轻量命令 / 测试执行
- 中断闸门：...

编码前检查单
- 技术栈：...
- 已读规范：core-standards.md, verification.md, ...
- 专项规则：启用/不启用，原因
- 关键条款：§4.4、§4.7、§5.7（只列与本步相关；除非任务跨越多个风险域，否则 **MUST NOT** 超过 5 条）
```

检查单条款 **MUST** 能在 reference 中找到。同一轮首次输出检查单或关键条款变化时，若脚本可用，**MUST** 运行 `scripts/check-refs` 机检引用真实性；脚本不可用时 **MUST** 人工核对并说明。

## 5. 自动执行与闸门

固定进入 `auto` 模式，**MUST NOT** 逐步询问开始确认。每步 **MUST** 按以下循环执行：

1. 拆解当前最小可验证任务/步骤，展示进度。
2. 检查依赖、风险和上下文预算，输出执行契约与编码前检查单。
3. 按规范最小改动实现，保持项目既有风格。
4. 执行验证并复核 `git diff`。
5. 输出中间短报告后自动进入下一步。

触发以下任一闸门时 **MUST** 中断执行循环并报告原因；除非需要用户裁决，否则 **MUST NOT** 提问：

- TASK 依赖未完成。
- 需求、设计或验收标准不明确，且会影响实现决策。
- 预计改动超过 8 个文件、跨越超过 2 个顶层模块、需要新增依赖、修改基础设施或触及危险操作。
- 发现实现冲突、敏感文件、权限/安全风险或无法自行裁决的规则冲突。
- 验证失败后已做 1 次最小范围修复仍失败，或继续修复会扩大范围。

## 6. 验证策略

- 每步 **MUST** 至少执行静态自检和 `git diff` 范围复核。
- 轻量命令、构建/测试边界、失败处理和未执行说明 **MUST** 按 `references/verification.md` 执行。

## 7. 报告与进度

中间短报告 **MUST** 固定压缩为：

```markdown
任务/步骤：... ✅/❌/🔄
改动：N files
验证：静态自检=...；diff=...；构建/命令=...；测试=...
下一步：...
```

最终汇总 **MUST** 包含：执行契约摘要、完成范围、变更文件与要点、验证等级与结果、技术栈判定、规范检查、TASK 状态更新、未执行验证及原因、剩余风险/后续建议、规范读取凭证（文件路径 + 条款数）。最终汇总 **MUST NOT** 复述完整规范原文、完整 diff 或未触发的检查项。

存在 TASK 文档时，**MUST** 同步当前任务状态：`✅ 已完成` / `🔄 进行中` / `⏳ 待执行` / `❌ 阻塞`。无 TASK 文档时 **MUST** 仅对话汇报，**MUST NOT** 为进度新建或改写文档。

## 8. docs 路径约束

本文档中的 `docs/` 一律指 AI 当前工作空间根目录下的 `docs/`。查找 TASK/PLAN/DRAFT、同步任务进度或更新 Markdown 时，只能写入该工作根目录 `docs/` 及其子目录，不写入子模块、子工程、包或服务目录下的 `docs/`。用户指定路径不合规时，改为合规路径并说明。

## 9. 辅助标定

- `scripts/check-refs.ps1` / `check-refs.sh`：校验检查单或报告中的 `§` 条款引用是否存在。
- `scripts/check-report.ps1` / `check-report.sh`：校验最终汇报是否包含执行契约、验证等级、未执行原因和规范读取凭证等必填块。
- `scripts/check-diff-scope.ps1` / `check-diff-scope.sh`：输出 diff 文件、模块和风险提示，辅助判断是否越界。

这些脚本是辅助标定工具，**MUST** 按触发条件运行而不是每步全量运行：同一轮首次输出检查单或关键条款变化时用 `check-refs`；最终汇总前或改动范围不明时用 `check-diff-scope`；需要机检报告结构时用 `check-report`。脚本不可用时，**MUST** 人工完成同等检查并在报告中说明。
