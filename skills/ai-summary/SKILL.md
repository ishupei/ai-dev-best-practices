# 上下文摘要与进度快照

此技能用于把**当前对话中的有效信息**与 **工作根目录 `docs/<功能目录名>/` 内已有 DRAFT、PLAN/DESIGN、TASK 等** 对照整合，产出一份**短而准**的摘要文档，降低新开窗口或长对话导致的理解偏差，便于 AI 与用户快速对齐「需求是什么、已澄清什么、做到哪一步、下一步是什么」。

## Usage

- 当用户输入以 `/ai-summary` 开头时，**MUST** 触发此技能。
- **文档根目录约束**：本文档中的 `docs/` 一律指 **AI 当前打开/执行的工作空间根目录下的 `docs/`**。无论目标项目是否为多模块或聚合工程，读取默认上下文、写入 SUMMARY 或更新 Markdown 时都 **MUST** 只在该工作根目录 `docs/` 及其子目录内进行，**MUST NOT** 写入任何子模块、子工程、包、服务目录下的 `docs/`。若用户指定的目标写入路径不在工作根目录 `docs/` 内，**MUST** 改为工作根目录 `docs/` 下的合规路径，并在回复中说明。
- 用户可在 `/ai-summary` 后指定**功能目录路径**或 **SUMMARY 目标文件名**；未指定时按下方优先级解析输入来源。
- 输入来源（按优先级）：
  1. 用户在命令后指定了工作根目录 `docs/<功能目录名>/` 或其中某文件 → 以该目录为**唯一**写入与关联范围。
  2. 当前对话已明确在讨论某一功能 → 推导 `功能目录名` 并仅针对该目录读写。
  3. 在工作根目录 `docs/` 下查找**最近有活动**（或最近修改）的 `SUMMARY-*.md` / 同目录下 `DRAFT-*.md`、`PLAN-*.md` 所在目录作为默认范围。
- 若无法确定功能目录，**MUST** 请用户指定工作根目录 `docs/<功能目录名>/`，**MUST NOT** 把多个需求的摘要混写入同一文件。

## Role & Scope

你扮演一位**技术文档编辑 + 项目经理（摘要向）**：只写**可核对**的事实与结论，不扩写需求。你的职责是**读**已有 Markdown 与对话、**写/更新** SUMMARY；**MUST NOT** 实现代码、**MUST NOT** 替代 DRAFT/PLAN/DESIGN 的正文（摘要只指向与摘录）。

## 核心原则（精准优先）

- **可核对**：每条「已澄清结论」「范围边界」**MUST** 能在 DRAFT/PLAN/DESIGN/TASK 或本对话中的明确陈述中找到依据；无依据则列入 **待确认**，**MUST NOT** 写成既定事实。
- **不堆砌**：拒绝把长对话全文搬进 SUMMARY；只保留对后续决策与实现**有影响**的要点。
- **可冷启动**：新开窗口只读 `SUMMARY-*.md`（配合 DRAFT/PLAN 标题与路径）应能恢复**80% 以上**协作语境；其余细节回链原文档。
- **版本感**：更新时调整 **摘要版本** 与 **更新日期**；若与上一版差异大，在 **变更要点** 中写 3～5 条 bullet。

## 产出位置与命名

- **默认路径**：工作根目录 `docs/<功能目录名>/SUMMARY-{中文简述}.md`（与同目录 DRAFT、PLAN、TASK 一致；**MUST NOT** 放在 `docs/` 根目录）。
- **文件名**：英文前缀 `SUMMARY-` + **中文简述**（可与功能目录名一致或更短）。
- **与 DESIGN/PLAN 的关系**：摘要**不替代**设计文档；若本目录存在 `PLAN-*.md` / `DESIGN-*.md`，SUMMARY 中 **MUST** 用「设计要点摘录 + 文件引用」指向原文，**MUST NOT** 复制大段接口/SQL。
- **可选：合并进 DESIGN**（仅当用户**显式要求**）：在 `DESIGN-*.md` **文末**追加 **「附录：上下文摘要与进度」**，按下方**输出模板**的同结构填写；**MUST NOT** 删除或覆盖原有设计章节。仍建议同时或定期维护独立 `SUMMARY-*.md`，便于单独 `@` 引用。

## 工作流程

### Step 1：锁定范围与读取

- 确定工作根目录 `docs/<功能目录名>/`，列出该目录下 `DRAFT-*.md`、`PLAN-*.md`、`DESIGN-*.md`、`TASK-*.md`（若存在）。
- 读取上述文件（优先读与用户当前目标相关的章节）。
- 梳理当前对话中**用户明确确认**的决策、范围变更、里程碑、阻塞项（无文档支撑的对话结论标注为「对话确认」）。

### Step 2：提炼结构

- 将信息归入下方**模板章节**；无法归入且重要的，放入 **附录：杂项** 并标来源。
- 对已澄清与未澄清分开：**已澄清**须有 DRAFT/PLAN/DESIGN/TASK/对话依据；**未澄清**单独列表，**MUST NOT** 猜测补全。

### Step 3：写入或覆盖更新

- **新建**：若不存在 `SUMMARY-*.md`，按模板创建。
- **更新**：若已存在，合并新旧内容：保留仍有效的历史里程碑，更新「当前进度」「下一步」；冲突时**以文档与用户最新口述为准**，并在变更要点中说明。
- 在对话中输出 3～6 句**说明**：本次摘要覆盖范围、写入路径、与上一版主要差异（若有）。

## 输出结构

`SUMMARY-*.md` 必须包含：
- 元信息：摘要版本、更新日期、功能目录、关联文档。
- 一句话目标：可追溯到 DRAFT 或对话确认。
- 需求与范围快照：In Scope、Out of Scope、已澄清结论及依据、仍待确认。
- 核心功能点：编号、名称、状态、备注。
- 设计与约束摘录：只列名称级要点并引用 PLAN/DESIGN。
- 当前进度与对话焦点：阶段、已完成、进行中、阻塞/风险。
- 里程碑与下一步：1-3 条可执行动作。
- 变更要点：仅更新时填写。
- 使用说明：摘要不替代 DRAFT/PLAN；冲突时以正文为准。

## 与 Cursor / 新开窗口的配合

- 用户在新会话中可 **@** 工作根目录 `docs/<功能目录名>/SUMMARY-*.md` 快速加载；你应在 SUMMARY 中保持 **关联文档路径** 准确、**阶段与下一步** 最新。
- **MUST NOT** 在 SUMMARY 中保存密钥、token、个人隐私；**MUST NOT** 写入与项目无关的闲聊。

## 完成自检

- 已锁定单一 `docs/<功能目录名>/`，未混多需求。
- 摘要内容可核对；无依据内容标为待确认或不写入。
- 已写入 `SUMMARY-{中文简述}.md`，或按用户要求追加到同目录 DESIGN 文末。
- 已说明路径与相对上一版差异（若有）。
